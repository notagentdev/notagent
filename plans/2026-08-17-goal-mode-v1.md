# Goal Mode — Self-Continuing Work Toward an Objective

## Objective

Take goal mode over from `../notagent-main-rust`: the user names an objective,
and the agent keeps working toward it turn after turn without being re-prompted,
until it reports the goal complete, reports itself blocked, or exhausts a budget.

Concretely, after this plan:

- `/goal ship the release --turns 20 --tokens 50000` starts a goal; `/goal`
  reports it, `/goal pause`, `/goal resume` and `/goal clear` control it.
- Two tools, `create_goal` and `update_goal`, let the model start a goal itself
  and — crucially — are the **only** way it leaves the continuation loop.
- A footer badge shows the running goal and what it has spent.
- One addition over the reference, taken from `../reasonix-main`: a `complete`
  claim while todos are still open is refused the first time. A second
  consecutive claim overrides it; `/goal strict …` never allows the override and
  asks for a quality self-check instead.

### Why the loop is left by a tool call and not by prose

This is the single design decision the whole feature rests on, and it is the
reason this source was chosen over the three alternatives surveyed:

- A model that merely writes "I am stuck" keeps the goal active and gets
  continued again. Only `update_goal` with status `blocked` stops the loop
  (`../notagent-main-rust/crates/notagent_app/src/hooks/goal.rs:11`).
- `../reasonix-main` parses markers such as `[goal:complete]` out of the model's
  prose (`internal/control/goal.go:24`), which is fragile in exactly the way an
  agent that writes code is likely to break: the marker can appear in a code
  block, a diff, or a quoted log line.

The reference's own weakness is that it takes the model's word for `complete`.
That is what the `../reasonix-main` graft fixes, and it is the only part of that
project this plan adopts.

### Assumptions

- **The goal lives in memory, not in the session file.** This port keeps todos
  in an in-memory store on the session (`crates/notagent/src/core/agent_session.rs:491`)
  with no persistence, and the goal follows todos. Consequence, stated plainly:
  a goal does not survive `/resume` or a restart. The reference persists it with
  the conversation because it has a conversation-scoped `Metrics` record to
  persist it in; this port has no counterpart. Alternative 1 covers the other
  choice.
- **No on/off setting.** Unlike the atomic leases (v0.1.19) and the bash filter
  (v0.1.20), goal mode needs no gate: it is inert until someone runs `/goal` or
  the model calls `create_goal`. The reference has no switch for it either.
- **The two tools are refused inside a subagent.** A delegated agent driving its
  own continuation loop inside its parent's loop is a runaway with no user in
  the room to stop it. `../kimi-code-main` binds its goal service at agent scope
  and rejects subagent callers for the same reason
  (`packages/agent-core-v2/src/agent/goal/goal.ts:5`).
- **Version.** The work lands as v0.1.21 (current workspace version is 0.1.20,
  `Cargo.toml:6`).

### The five states and who may leave them

`Active` is pursued automatically. `Paused` is the user's stop and `Blocked` is
the agent's; both resume the same way. `BudgetLimited` and `Complete` are the
other two ends. From the model's side `Blocked`, `BudgetLimited` and `Complete`
are all terminal — only the user leaves them
(`../notagent-main-rust/crates/notagent_domain/src/goal.rs:19`).

Two budgets run in parallel and whichever runs out first stops the goal: tokens,
derived from the conversation's cumulative spend against a baseline taken when
the goal started, and continuation turns, which are the blunter measure but the
only one that bounds wall-clock cost on a model whose tokens are cheap.

Three separate things stop a runaway, and all three are worth having: either
budget; a hard cap of 25 continuations inside one user turn, which a real user
message resets; and the fact that a reminder is only injected when the previous
one is not still standing unanswered.

### Where it attaches in this port

Every integration point already exists, which is what makes this the cheapest of
the four candidates:

- **The turn-end point.** `dispatch_hooks` handles `AgentEvent::TurnEnd` with an
  empty `tool_results` — no further tool calls, so the run would end — and that
  is exactly where open todos are handed back today
  (`crates/notagent/src/core/agent_session.rs:747` and `:762`). The goal driver
  belongs beside `remind_about_open_todos`.
- **The continuation channel.** `remind_about_open_todos` reaches the next turn
  through the session's follow-up channel
  (`crates/notagent/src/core/agent_session.rs:1915`). That is the port's
  equivalent of the reference pushing a message onto the conversation context,
  and it is what makes the loop continue.
- **Todos**, for the completion check (`crates/notagent/src/core/agent_session.rs:491`).
- **Token totals**, for the token budget (`crates/notagent/src/core/usage_totals.rs:10`).
- **Tool registration**, `ToolName` and `create_tool_definition`
  (`crates/notagent/src/core/tools.rs:170`).
- **The slash-command pattern**, established twice now by `/leases` and
  `/bash-filter` (`crates/notagent/src/core/slash_commands.rs:62`).
- **The footer**, `crates/notagent/src/core/footer_data_provider.rs`.

### What the reasonix graft actually is

`../reasonix-main/internal/control/goal.go:357` runs a small state machine at
every turn end. The part worth taking is its handling of a completion claim: if
todos remain open and either strict mode is on or this is the first claim, the
claim is refused and the outstanding work is named back. Otherwise, in strict
mode, a one-time quality self-check runs before the goal is allowed to finish.

The rest of that machine — marker parsing, idle detection, the block counter,
the 50-turn ceiling — is either fragile or already covered by the reference's
budgets and continuation cap, and is not taken.

## Verification Criteria

- `./scripts/check.sh` passes: `cargo fmt --check`, `cargo clippy --workspace
  --all-targets -- -D warnings`, and `cargo test --workspace`.
- All 15 ported state-machine tests pass with unchanged expected values.
- `/goal ship it --turns 3` starts a goal; the agent runs three continuation
  turns unprompted, then the wrap-up reminder appears once and the badge reads
  `budget reached`.
- An agent that writes "I am stuck" without calling `update_goal` is continued
  again; one that calls `update_goal` with `blocked` and a reason stops, and the
  reason is what `/goal` reports.
- `update_goal` with `complete` while a todo is open is refused and names the
  open item; the immediately following `complete` succeeds; anything in between
  resets that.
- Under `/goal strict …` the refusal never yields, and once the todos are done
  the first `complete` produces the self-check turn rather than finishing.
- Neither `create_goal` nor `update_goal` is present in a subagent's tool set,
  and a call that reaches one anyway is refused.
- An objective containing angle brackets reaches the model escaped and inside the
  untrusted wrapper.
- With no goal, `bash`, the agent loop and the footer behave byte-identically to
  today — the whole existing suite passes unchanged.
- `/goal` with no goal says so; `/goal <objective>` with a goal already running
  reports the running one and leaves it alone; `replace` overwrites it.
- 25 continuations inside one user turn stop the loop; a real user message
  resets the count.

## Potential Risks and Mitigations

1. **A goal that never terminates burns the user's budget unattended.**
   This is the failure mode the whole feature is one bad prompt away from.
   Mitigation: port all three of the reference's independent stops rather than
   any one of them — the token budget, the turn budget, and the 25-continuation
   cap per user turn — and cover each with its own test. The cap is the one that
   holds when the user gave no budget at all, so it is not optional.

2. **The agent declares victory on unfinished work.**
   The reference trusts the model's `complete`.
   Mitigation: tasks 7 and 8, the graft from `../reasonix-main`. The override
   exists because a stale checklist is common and trapping a finished agent
   would be worse; strict mode exists because for a long unattended run the
   checklist is the contract.

3. **The continuation reminder is mistaken for a user message.**
   The driver recognises its own reminders by their opening phrase in order to
   suppress duplicates and to find where the current user turn began. A reworded
   reminder that no longer matches its own detector would silently disable both.
   Mitigation: keep phrase and text tied together the way the reference does, in
   one constant used for both rendering and detection, and add a test that
   asserts a rendered reminder is recognised by the detector.

4. **A subagent starts its own goal.**
   Nested continuation loops multiply turns with nobody watching.
   Mitigation: task 4 — excluded from the roster *and* refused at the tool, with
   a test for the refusal rather than only for the roster.

5. **The objective carries an injection.**
   It is user text replayed into a prompt every turn.
   Mitigation: task 6 — the untrusted wrapper and escaping the reference already
   applies, with a test that feeds markup through.

6. **A goal silently disappears on resume.**
   The in-memory choice is deliberate but surprising.
   Mitigation: task 12 documents it, `/goal` says plainly when there is no goal,
   and Alternative 1 records what changing the decision would cost.

## Alternative Approaches

1. **Persist the goal with the session.** A goal would survive `/resume` and a
   restart, matching the reference, which keeps it in the conversation's
   persisted metrics. Rejected for now because this port persists no
   session-scoped tool state at all — todos included — so it would mean
   inventing that mechanism for one feature. Worth revisiting together with
   todos, since both want the same thing and neither wants its own answer.

2. **Take the completion check from `../grok-build` instead.** Its goal
   classifier spawns independent skeptic subagents that judge whether the
   objective was really met, which is the only approach among the four surveyed
   that verifies rather than trusts. Rejected as out of scope: roughly 19k lines
   with its own event protocol and a subagent-spawn path that bypasses the
   ordinary delegation tool, and it costs several extra model runs per
   completion. The todo refusal buys much of the benefit for two orders of
   magnitude less.

3. **Take `../reasonix-main` whole.** Its state machine also brings idle
   detection, a repeated-block counter and a hard 50-turn ceiling. Rejected
   because it drives everything off markers parsed out of the model's prose,
   which an agent that writes code will eventually produce by accident, and
   because the budgets and the continuation cap from the reference already cover
   the ceiling. Idle detection — several turns with no tool call — is the one
   further idea worth considering later.

4. **A goal queue, as in `../kimi-code-main`.** Several objectives lined up, the
   next starting when the previous finishes. Genuinely useful and the only
   feature of the four that no other has. Rejected as a separate decision: it
   only means anything once a single goal works, and it brings its own UI.
