# Conventions

These rules apply to the entire Rust workspace.

## 1. Workspace layout

- The Cargo workspace uses `members = ["crates/*"]`; adding a crate does not
  require changing the root manifest.
- Responsibilities follow crate boundaries. Shared interfaces stay small and
  are exposed through the relevant library APIs.

## 2. Module layout

- Directory modules use the `mod.rs`-free form, such as `core/tools.rs` beside
  `core/tools/`.
- Established module, type, and constant names are not changed merely for taste.
- Use `pub` only for surfaces that are genuinely needed across crate boundaries;
  helpers remain private.

## 3. Error handling

- Library crates use small, descriptive `thiserror` types.
- User-facing, model-facing, and protocol errors are stable product surface and
  must remain understandable and contextual.
- `anyhow` is limited to binary and command boundaries, never public library APIs.
- Expected failures use `Result`. New production paths must not abort with
  `unwrap()` or `expect()`.

## 4. Async and concurrency

- The application runs on Tokio's multi-thread runtime. Subagents and shell jobs
  are real asynchronous tasks.
- Cancellation uses `tokio_util::sync::CancellationToken`. Long-running paths
  check it at loop boundaries, around awaits, and between tool calls.
- Library code never uses `block_on`.

## 5. Dependencies

- Versions live exclusively in `[workspace.dependencies]` in the root
  `Cargo.toml`; crates use `dep = { workspace = true }`.
- New dependencies need a concrete technical benefit and are not introduced for
  small helper functions.
- `serde_json` uses `preserve_order` so schemas, settings, and persisted data
  serialize deterministically.
- `Cargo.lock` is committed and generated by Cargo, never edited by hand.

## 6. Tests

- Unit tests live beside the code in `#[cfg(test)] mod tests`. Integration tests
  live under `crates/<crate>/tests/`.
- Test names describe behavior. Assertion messages name the broken rule and show
  the observed value.
- Tests do not require network access or real provider keys. Provider behavior is
  exercised with the faux provider or local loopback servers.
- When a test fails after a change, decide deliberately whether the code or the
  expectation is wrong. Pre-existing failures are demonstrated separately and
  are not changed in passing.

## 7. TUI line type

Rendered TUI lines are shared: `Component::render` returns `Vec<Line>` with
`Line = Arc<str>`. This keeps cache hits cheap and lets the differential renderer
recognize unchanged lines by pointer identity.

- Both renderers check pointer identity first and fall back to content equality.
  Lost identity may make a frame slower, but must never change its output.
- The markdown component caches normalized, finished lines. The paint path must
  not normalize or finish those lines again.
- `BoxComponent` removes a child's trailing reset before applying a background
  wash so the color reaches the right edge.

## 8. Commits

- Every subject starts with `fix:` or `feature:` and explains the reason in
  English prose.
- `scripts/check.sh` must pass completely before merging.

## 9. Formatting and lints

- Run `cargo fmt` with the default configuration.
- `cargo clippy --workspace --all-targets -- -D warnings` must pass.
- `#[allow(...)]` is permitted only locally with a technical justification.
- The complete verification command is `scripts/check.sh`.
